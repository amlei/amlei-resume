# 原始素材提取（ingestion）

用户提供的一切原始文件（`.docx` / `.pdf` / `.pptx` / `.xlsx` / 项目代码 / 设计稿 / 数据集等），是事实层的**提取源**和未来**回溯凭证**。本文件定义素材的获取、转换、归档流程。

## 核心原则：原始文件永不写临时目录

转换结果和原始文件都**落盘到 `_shared/files/`**——不写 /tmp、不写 task-local 目录。否则下次想回溯原始材料就找不到了，事实层失去可验证性。

## 流程

### 步骤 1：归档原始文件

```bash
cp <用户给的文件路径> _shared/files/<原文件名>
```

重名时备份再覆盖（带时间戳）。多文件按原结构归档。

### 步骤 2：转换文档类为 Markdown

仅文档类（.docx / .pdf / .pptx / .xlsx）需转换。代码 / 配置 / 数据 / 设计稿等非文档文件，**直接读源内容**，不靠摘要或文件名猜测。

```bash
markitdown <原始文件> -o _shared/files/<原文件名>.md
```

转换结果与原文件**同目录**（`_shared/files/`）。

### 步骤 3：下钻读真实内容，不停在概览

README / landing page / 摘要 / 目录列表只是地图，不是地形。必须下钻到材料的实际内容：

- 网页链接 → 钻进它的实际内容（仓库里的具体文件、文档全文、真实数据记录），不能只读 README
- 本地文件 → 用 markitdown 转全文（文档类）或直接读源（代码/配置）
- 目录 → 不止浏览文件列表，逐个读关键文件的实际内容

把理解写入任务局部的 materials.md / 分析.md，后续事实提取（写入 `_shared/`）从这里取材。

### 步骤 4：从素材提取事实

读完素材后，**带推理去读**——材料里凡是暗示了用户没明说的工作、职责、经历的细节，都是线索，转成待问问题记入 materials.md「待问疑点」区。可挖的维度（示例，非穷举）：

- **没明说的职责**：协作记录里别人的任务是你建的 → 你是不是还做了协调？
- **时间转折 / 空白**：不同时期领域、技术栈、岗位发生变化 → 问怎么过渡
- **规模 / 协作范围**：经手的量级、对接人数，往往暗示比"执行者"更大的职责
- **任何没看明白、想确认的细节**

挖出来的、确认过的内容才能进事实层（经评估 agent + 用户确认，详见 [facts.md](facts.md) 的"写入流程"）。

## 可挖线索维度

用户给的材料往往比他自述更多——人会习惯性低报自己做过的事。带着"他还做过什么没说"的眼光去读，不要预设"某岗位就不该做别的活"。

## 失败处理

markitdown 转换失败时：

- **原文件仍归档**到 `_shared/files/`（不丢弃）
- 把错误 surface 给用户
- 改用其他方式读内容（如直接读 pdf 文本、用 LLM 多模态读图像化文档）
- 若彻底读不出，标注 `_shared/files/<文件名>.unreadable.md`，记录失败的尝试

## 头像提取（特例）

旧简历含照片时，从原 docx/pdf 提取头像：

```bash
python3 <amlei-resume>/scripts/extract_avatar.py <原始文件> _shared/files/avatar.png
```

抽到后写入 `identity.json.avatar.ref = "files/avatar.png"` + `extracted_from = "<原文件>"`。抽不到人脸则留空，不瞎填路径。
