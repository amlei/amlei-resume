# 岗位调研

> 用途：用岗位证据回答“该投什么、该突出什么、还缺什么”，为简历定位、选材和表达提供依据。
>
> 这里研究的是外部岗位要求，不替用户补个人事实。调研结论可以改变表达优先级；没有候选人的证据，不能把岗位要求写成候选人能力。
>
> 只使用公开网页搜索和可核验的招聘页面，不调用招聘平台的自动化采集脚本。

## 先确定要做的判断

调研前先写清一个问题：这次要决定的是方向、候选层级、行业/公司取舍、能力优先级，还是某个具体岗位的匹配方式？

没有目标 JD 时，先建立岗位样本；只有一个目标 JD 时，先提取要求，再用达到最低样本量的同类高质量 JD 判断哪些是公司特性、哪些是行业共性。不要用单一 JD 或少数几家公司代替市场，也不要把薪资排名当成岗位定位。

候选人的经验年限只用于判断当前可投性和表达顺序，不得作为搜索或排除 JD 的条件。目标方向下不同经验层级的 JD 都进入能力样本，并单独记录层级差异。

## 输入

开始搜索前确认以下信息；缺失项可以基于已有目标做合理假设，但要在报告中标明。

| 信息 | 要确认什么 |
|------|------------|
| 目标岗位 | 岗位名称、同义 title、可能相邻的岗位族 |
| 求职范围 | 城市、远程、是否接受异地 |
| 行业与公司 | 目标行业、公司类型、规模阶段、业务模式 |
| 候选阶段 | 校招、社招、转行，用于后续可投性和表达排序；不作为 JD 收集门槛 |
| 已有样本 | 用户提供的 JD、目标公司、招聘链接或排除项 |

岗位名称不能直接当范围。以产品岗位为例，同一个 title 在不同公司可能分别偏业务、平台、增长、解决方案或交付；先列出同义词和相邻岗位，再决定哪些样本属于同一比较对象。

## 产物与边界

- `research/jd-{company}.md`：保存单个公司的原始 JD 摘录、来源与日期。
- `research/jd.md`：汇总多份 JD 的统一字段矩阵，用于横向比较。
- `research/市场报告.md`：面向本次求职决策的综合结论。

原始 JD 是证据，市场报告是判断。不要把长段 JD 原文复制进市场报告，也不要让调研报告直接改写简历。

目录与命名以 [file.md](file.md) 为准。

## 调研流程

### 1. 收集代表性 JD

按岗位族、行业/公司类型、层级、城市/工作方式选择样本，而不是只搜一个 title 或一页招聘结果；不需要铺满所有组合，但必须满足最低数据量。

默认样本门槛：

- **单一岗位方向、单城市/远程，首轮调研**：至少 30 份有效 JD，来自至少 15 家合格公司。
- **多城市、跨行业或完整市场报告**：至少 50 份有效 JD，来自至少 25 家合格公司，并覆盖至少 3 类公司画像。
- 同一公司、同一岗位、同一版本的重复转载只算 1 份；同一公司的相似岗位按层级去重，避免一家公司贡献大量近似样本。
- 单一公司最多贡献 2–3 份不同层级/方向的 JD；超过时作为补充样本，不参与总体频率的主统计。
- 细分岗位确实不足时，可以扩展同义 title、相邻城市或相近岗位，但必须在报告中标注 `样本不足`；不能用外包、匿名或不相关公司的 JD 凑数。

来源质量优先于数量：

1. **A 类：核心样本**：目标公司、大厂、上市公司、业务稳定且公开可验证盈利/融资/市场地位的公司、头部 AI 产品团队或有代表性的直接竞品。优先使用公司官网/官方招聘页。
2. **B 类：补充样本**：垂直行业龙头、成长期但有明确产品与市场声誉的公司，用于观察业务模式差异。
3. **C 类：背景样本**：普通中小企业、外包/人力派驻、匿名转载或信息不完整页面。默认不进入主统计；只有能提供独特职责或明确目标公司时才补充，并标注来源级别。

“大厂”和“有名气”不能只看品牌宣传；能核验财务状况时记录公开依据，不能核验时标为未知。公司的规模、融资阶段、盈利/亏损、裁员或经营风险属于公司画像，不替代对岗位本身的分析。

优先选能说明差异的样本：

- 目标公司与直接竞品；
- 大厂、上市公司和财务状况健康/市场地位清晰的头部公司；
- 不同业务模式的同岗位，例如平台型、项目交付型、内容型或企业服务型；
- 同一方向的所有经验层级；经验要求只做标注和分层，不作为采样过滤；
- 最近 6–12 个月的公开 JD。

停止采集的条件必须同时满足：

- 已达到对应场景的最低 JD/公司数量；
- 最近新增 10 份高质量 JD 没有带来新的职责、能力、层级或业务模式差异；
- 已覆盖目标城市、公司类型和全部经验层级。

达不到最低数据量时，不得输出确定性市场结论，只能写“初步观察”，并说明缺口。

### 2. 提取 JD 证据

每份 JD 先统一成同一组字段，再做比较。

| 字段 | 记录什么 |
|------|----------|
| 来源 | 公司官方招聘页、招聘平台或转载；原始 URL |
| 时间 | 发布日期与访问日期；只有访问日期时明确标注 |
| 公司画像 | 行业、业务模式、公司类型、规模/阶段（可确认时） |
| 岗位 | 原始 title、所属团队、岗位族、职级 |
| 经验门槛 | 不限 / 应届 / 1–3 年 / 3–5 年 / 5 年以上；按 JD 原文记录 |
| 工作方式 | 城市、远程、出差或驻场要求 |
| 职责 | 解决什么问题、对什么结果负责、与谁协作 |
| 必备要求 | 明确写出的硬性条件与经验 |
| 加分要求 | “优先”“熟悉”“有……经验更佳”等 |
| 领域与工具 | 业务领域、技术/工具、方法论 |
| 衡量方式 | 指标、交付物、客户或业务结果 |
| 薪酬 | 原始口径与范围；未写就标“未提供” |

提取时保留原词，再在汇总层做同义词归并。不要因为模型知道某个岗位“通常要求”什么，就把 JD 没写的要求补进去。

### 3. 合成岗位判断

先分组，再下结论：

- **按岗位族分层**：同一 title 下的不同职责组合，分别说明典型目标和能力。
- **按行业/公司类型比较**：哪些要求来自业务模式，哪些是全行业共性。
- **按层级比较**：所有层级都进入能力样本；先提炼跨层级共性，再区分初级更看执行与基础判断、高级更看范围、决策、结果和带动他人的能力。
- **区分市场能力和当前可投性**：前者来自全层级高质量样本，后者单独判断用户当前能否命中；不得因为用户经验年限不足而删除高级 JD 暴露出的能力方向。
- **区分必备与加分**：高频出现不等于硬性要求，必须结合原 JD 的措辞。
- **识别近期变化**：对比最近 6–12 个月与更早样本，说明哪些能力从加分项变成常见要求、职责是否扩展。没有足够历史样本时，只写“当前样本显示”，不编造趋势。
- **城市分布**：作为机会密度和薪酬差异的背景，不替代行业、公司类型和岗位族分析。

### 4. 薪酬口径

薪酬必须和岗位层级、城市、公司类型一起解释。记录：

- 月薪还是年薪；
- 固定薪资、总包还是含奖金/股权；
- 12、13、14、15 薪等口径；
- 校招还是社招；
- 样本数与区间；样本足够时再给中位数，不能只给一个看似精确的平均值。

样本少、口径混杂或只有匿名爆料时，降低置信度并写清限制；不要用不同口径直接平均。

### 5. 映射回候选人与简历

调研只有落到筛选决策才有用。结合 [screening.md](screening.md) 输出：

- 全层级样本得到的共性能力，以及按经验层级变化的要求；
- 当前可投岗位与作为成长目标的岗位，分别说明命中与缺口；
- 第一轮筛选者最可能找的字段；
- 目标岗位的 ATS 关键词，以及候选人是否有证据支撑；
- 最该前置的项目、经历和结果；
- 明显缺口：必备项缺证据、只有加分项、层级不匹配、领域迁移风险；
- 针对不同公司类型应调整的选材重点；
- 面试官最可能追问的能力与边界问题。

指标必须与业务模式匹配：

- ToC / 增长型岗位可以关注用户量、留存、转化、活跃和裂变。
- ToB / ToG / 项目交付型岗位不得默认套用这些指标；优先评估 POC/Pilot、试点范围、交付周期、人工环节减少、准确率、单条成本、客户确认/验收、复购或扩点等证据。
- 候选人没有某类业务数据时，应判断该指标是否属于目标岗位的真实要求，而不是机械列为“证据缺口”。

缺证据时，先回到 `materials/` 查材料或向用户追问；仍然没有就标为缺口，不把“可以学”“了解过”包装成已具备。

## 来源与置信度

按以下优先级取证据：

| 层级 | 来源 | 用法 |
|------|------|------|
| 一手 | 公司官方招聘页、招聘方在招聘平台发布的原始 JD、官方薪酬/人才报告与公开说明 | 判断岗位要求与公司差异的主要依据 |
| 二手 | 第三方转载或聚合的 JD、薪酬聚合、行业报告 | 扩展样本、观察区间与共性 |
| 三手 | 媒体文章、培训/SEO 内容、个人总结 | 只补背景或线索，不单独支撑关键结论 |

每条关键结论标注来源与日期。来源冲突时并列呈现，不强行统一；无法确认的内容标“未知”或“低置信度”。

## 市场报告结构

报告按决策顺序写，不按搜索过程写：

1. **决策摘要**：这次调研支持什么判断，最重要的三点是什么。
2. **范围与样本**：搜了什么、覆盖哪些行业/公司/层级、有效 JD 数、公司数、A/B/C 类来源数量、经验门槛分布与时间。
3. **岗位分层**：同 title 下的主要职责类型及差异。
4. **行业与公司差异**：哪些要求由业务模式决定。
5. **能力要求**：必备、加分、ATS 关键词及出现频率；同时给出全层级共性和按经验层级的差异。
6. **薪酬**：按层级、城市和口径呈现，附样本数与限制。
7. **近期变化**：最近 6–12 个月可观察到的要求或职责变化。
8. **简历映射**：筛选字段、应前置的证据、公司类型适配、与业务模式匹配的成果指标，以及“当前可投”与“成长目标”的差异。
9. **证据缺口**：候选人缺什么、需要补问什么、哪些要求只能视为加分。
10. **来源、日期与局限**：逐条列出来源；说明样本偏差、缺失信息与置信度。

## 交付前检查

- 调研问题是否对应一个真实的求职决策？
- 是否覆盖了岗位同义词、相邻岗位与不同公司类型，而不是单一 JD？
- 是否达到相应场景的最低 JD/公司数量；未达到时是否明确标为样本不足？
- 样本是否以大厂、上市公司、财务/市场地位可核验的头部公司为主，而不是随意抓取普通公司或外包岗位？
- 是否覆盖全部经验层级，并把经验门槛用于分层而不是采样过滤？
- 是否区分岗位共性、公司特性和样本噪声？
- 必备与加分是否回到原 JD 措辞判断？
- 薪酬是否标清月/年、固定/总包、薪资月数、校招/社招与样本数？
- 是否明确写出最近 6–12 个月的变化依据；样本不足时是否降低结论强度？
- 是否把结论映射到第一轮筛选字段、简历证据与缺口？
- 成果指标是否与目标公司的 ToB、ToC、ToG 或项目交付模式一致，而不是一套指标套所有岗位？
- 每个关键事实是否有来源、日期和置信度？未知项是否保持未知？
